# Introduction

## [The problem]

High-dimensional data is now routine across scientific computing, from genomics and single-cell transcriptomics to cheminformatics, proteomics, and computer vision ($$). Projecting such data into two dimensions for human inspection has become a reflexive first step of any exploratory analysis, and two methods — t-SNE ($$) and UMAP ($$) — dominate that step almost to the exclusion of alternatives. Both produce point clouds in which local position is informative but topology is not: clusters are visible, yet there is no principled way to trace how one cluster connects to another, no unique path between two points, and no structure to interrogate beyond visual inspection. Recent work has questioned how faithfully these embeddings preserve anything beyond coarse cluster identity — Chari and Pachter ($$) showed that a purpose-built autoencoder can force single-cell data into the silhouette of an elephant while scoring comparably to UMAP on standard quality metrics — and a parallel rebuttal argues the critiqued metrics miss the neighborhood and cluster-preservation properties that matter in practice ($$). The debate concerns what a 2D *point cloud* can and cannot carry; a tree sidesteps it by returning a different object, one in which shortest paths, neighborhoods, and edge weights are defined by construction rather than optimized stochastically. For many downstream questions — "what is the series of intermediates between these two molecules?", "through which transitional states does this cell lineage pass?", "which fold classes border this one?" — a scatter plot is the wrong object.

## [The original TMAP]

TMAP ($$) proposed a different answer. Rather than optimizing a stochastic embedding that preserves local neighborhoods on average, TMAP builds a k-nearest-neighbor graph, extracts its minimum spanning tree, and lays the tree out in the plane. The resulting object is not a point cloud but a navigable structure: every pair of points is connected by a unique shortest path along the tree, and that path is itself interpretable as a sequence of nearest-neighbor transitions through the data. TMAP was applied to large chemical libraries including ChEMBL and natural-product collections ($$) and established the tree as a credible alternative to t-SNE/UMAP for these domains. However, the original implementation was a C++ monolith with Python bindings, supported only Jaccard distance over binary fingerprints out of the box, offered no incremental updates, no scikit-learn integration, and did not scale comfortably past roughly one million points.

## [What has changed]

The data landscape has shifted substantially in the five years since. AlphaFold DB now contains over 200 million predicted protein structures ($$); public single-cell atlases routinely reach tens of millions of cells ($$); and general-purpose embedding models — ESM ($$) for proteins, CLIP ($$) for images, sentence transformers ($$) for text — produce dense, continuous vectors rather than the sparse binary fingerprints that TMAP was originally designed around. At the same time, approximate nearest-neighbor indexing has matured: HNSW ($$) and its modern implementations (FAISS ($$), USearch ($$)) deliver high recall at a fraction of the cost of locality-sensitive hashing on dense metrics. A tool built for binary Jaccard and million-point ceilings no longer matches the problems its users want to solve. What is needed is a library that handles cosine and Euclidean metrics on dense embeddings, scales to hundreds of millions of points, supports incremental updates and out-of-sample projection, and integrates cleanly with the Python scientific ecosystem — while preserving the tree abstraction that made the original method worth using.

## [What this paper presents]

We present TMAP2, a ground-up rewrite of TMAP along these lines. The indexing layer is pluggable: USearch-backed HNSW for cosine, Euclidean, and binary Jaccard at ≥99% recall@20; a Numba-accelerated MinHash + LSH-Forest implementation preserving the original Jaccard pipeline for backward compatibility; and direct ingestion of precomputed k-NN graphs from external tools such as MMseqs2 ($$), Foldseek ($$), and BLAST ($$). Tree layout is delegated to OGDF ($$), and interactive visualization is handled by regl-scatterplot ($$), which replaces the original Faerun front end and renders multi-million-point trees in the browser via WebGL; a jupyter-scatter ($$) binding brings the same interaction into notebooks. We expose this functionality behind a scikit-learn-compatible ($$) estimator API (`TMAP.fit`, `fit_transform`, `transform`, `add_points`, `save`, `load`) and provide graph-analysis utilities (tree paths, subtree purity, boundary edges, path properties) together with first-class domain modules for chemistry, proteins, and single-cell data. We benchmark the new pipeline against the original TMAP and against UMAP on datasets ranging from ten thousand to several million points, and we demonstrate the resulting maps across more than ten domains, from molecular libraries and AlphaFold-derived fold space to image collections of pet breeds.

## [Why trees, not embeddings]

The tree is not a cosmetic choice. In a minimum spanning tree the path between any two nodes is unique, and every edge corresponds to a concrete nearest-neighbor relationship in the original space. This turns questions that are ill-posed on a t-SNE or UMAP plot into questions with well-defined answers: the shortest chemical-space path between two drugs is a specific ordered sequence of molecules; the route through cell-state space between a progenitor and a differentiated cell is a specific ordered sequence of cells; the interpolation between two protein folds is a specific ordered sequence of structures. Point-cloud embeddings can suggest where such paths might lie; a tree makes them first-class objects that can be extracted, measured, and walked. TMAP2 is built around the claim that, for a growing set of exploratory workflows, this is the more useful abstraction.
